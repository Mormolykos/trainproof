# Checkpoint Fixtures

This directory contains small torch checkpoints used as fixtures for trainproof v0.16. Each fixture encodes a specific edge case for validation: `clean.pt` has all-finite weights and an optimizer state; `nan_weights.pt` contains exactly two NaNs in one named tensor; `inf_weights.pt` contains three Infs; `dead_layer.pt` has a tensor that is completely zeroed out; `no_optimizer.pt` contains model weights without an optimizer state dict; `shape_drift.pt` modifies the shape of one tensor compared to the clean baseline; and `mixed_dtype.pt` stores tensors in float32, float16, and bfloat16. The `oracle.json` file is generated by `oracle.py` (using torch directly) and records, per tensor: dtype, shape, numel, NaN count, Inf count and whether it is all-zero.

> **Correction (2026-09-21).** This paragraph used to describe the oracle as *"the
> ground truth reference against which trainproof's custom checkpoint parser must
> be validated."* **No such parser exists.** `grep -rn "nan_count\|is_all_zero\|inf_count"
> src/trainproof/` returns nothing, and no test reads `oracle.json`. The shipped
> `check_checkpoint` reads the ZIP directory only — CRC and the presence of
> `data.pkl` — and returns `TP-ENV-CKPT-OK` at level PASS for **all seven fixtures
> here, the pathological ones included**. Two independent forensic audits executed
> that and got 7/7.
>
> These fixtures and this oracle therefore describe a capability that was designed
> and never implemented. They are kept because they are the correct specification
> for it: a reader that never unpickles must reproduce exactly what torch reports.
> Building it is vNext work and is **not** in this release.

torch is used here and only here. It is the reference implementation, not the
product: the point of these fixtures is that a reader which never unpickles must
reproduce, exactly, what torch reports after unpickling. This mirrors how the
TensorBoard reader in v0.14 was validated against `EventAccumulator` rather than
against itself.

Two properties of this set matter more than the obvious ones:

- **`layer1.bias` is all-zero in every fixture, `clean.pt` included.** A
  zero-initialised bias is normal. Any "dead tensor" rule that flags all-zero
  tensors indiscriminately therefore returns a FAIL on a healthy checkpoint —
  the same class of false positive as `TP-ZERO-GRAD` in v0.14. This set makes
  that mistake impossible to ship unnoticed.
- **`mixed_dtype.pt` carries bfloat16**, which has no `struct` format code. A
  pure-Python reader must decode it as the upper 16 bits of a float32, so the
  fixture forces the case to be handled rather than discovered in production.

Regeneration is seeded (`torch.manual_seed(0)`); re-run `make_fixtures.py` then
`oracle.py` together, never one without the other.
